# Integration

How a forge crate builds on pipelith: what it supplies, what pipelith
owns, and the path a config file takes to a checked-in pipeline. A forge
crate is a CI materializer for one forge; actlith is the one for GitHub
Actions.

## Who owns what

pipelith owns what every forge shares:

- the pipe-table grammar of the config file (`registry`);
- the neutral `## workflows` rows, the kind catalogue and its checks
  (`kind`), and the nix system names (`system`);
- a YAML writer that cannot emit malformed YAML (`yaml`);
- the generated header, the write and the drift check (`files`);
- proposed rows from tracked files and the first config file (`detect`).

The forge crate supplies the rest: its config file name, its forge-only
sections, kinds and argument keys, its pipeline model lowered to a
`yaml` tree, a `yaml::Dialect` for its expression syntax, its runner and
pin tables, and where each file lands. pipelith depends on no forge
crate, and nothing forge-specific is written here.

## Depending on pipelith

Take it from crates.io:

```toml
[dependencies]
pipelith = "0.1"
```

To build against an unreleased commit, take it as a git dependency
pinned to a full commit instead:

```toml
[dependencies]
pipelith = { git = "https://github.com/pr0d1r2/pipelith", rev = "<full commit>" }
```

Allow that one URL in `deny.toml`:

```toml
[sources]
allow-git = ["https://github.com/pr0d1r2/pipelith"]
```

and give the nix build its hash, in `rustPlatform.buildRustPackage`:

```nix
cargoLock = {
  lockFile = ./Cargo.lock;
  outputHashes."pipelith-0.1.0" = "<hash nix reports>";
};
```

## From config file to pipeline

The example renders one file per `## workflows` row. Its `name` key
stands in for a real pipeline model; the real one is the forge crate's
own types, lowered to `yaml` entries. It runs as a doctest, so it
matches the API.

```rust
use std::error::Error;
use std::path::Path;

use pipelith::files::{self, File, Stale};
use pipelith::kind::{self, Extras, RawRow, Row};
use pipelith::registry::{self, Schema};
use pipelith::yaml::{self, Dialect, Entry, Node, Text, Value};

/// The forge's expression syntax: GitHub's, as an example.
struct Github;

impl Dialect for Github {
    fn expr(&self, inner: &str) -> Option<String> {
        let broken = inner.contains("${{") || inner.contains("}}");
        (!broken).then(|| format!("${{{{ {inner} }}}}"))
    }

    fn escape(&self, lit: &str) -> String {
        lit.replace("${{", "${{ '${{' }}")
    }
}

const CONFIG: &str = ".actlith";

fn render(text: &str) -> Result<Vec<File>, Box<dyn Error>> {
    // The grammar, against this forge's sections.
    let schema = Schema {
        sections: &[kind::WORKFLOWS],
    };
    let doc = registry::parse(CONFIG, text, &schema)?;
    // No forge-only kinds or keys in this example.
    let extras = Extras::default();
    let mut out = Vec::new();
    for cells in doc.section(kind::SECTION) {
        // The neutral row, checked against the catalogue.
        let raw = RawRow::from_cells(CONFIG, cells)?;
        let spec = kind::resolve(&raw, &extras)?;
        let row = Row::check(spec, &raw, &extras)?;
        // The forge's pipeline model, written by pipelith's writer.
        let name = Node::Value(Value::Text(Text::lit(&row.id)));
        let body = yaml::document(&Github, &[], &[Entry::fixed("name", name)]);
        out.push(File {
            path: format!(".github/workflows/{}.yml", row.id),
            bytes: format!("{}{body}", files::header("actlith", CONFIG)),
        });
    }
    Ok(out)
}

fn main() -> Result<(), Box<dyn Error>> {
    let text = "format 1\n\n## workflows\n\nid|kind|systems|cache|args\n\
                lint|gate|-|-|-\n";
    let rendered = render(text)?;
    assert_eq!(
        rendered[0].bytes,
        "# generated by actlith gen from .actlith; do not edit\n\
         ---\nname: lint\n",
    );
    // Before `files::write`, the file is missing under an empty root.
    let root = Path::new("no-such-root");
    let stale = files::check(root, &rendered)?;
    assert!(matches!(stale.as_slice(), [Stale::Missing(_)]));
    Ok(())
}
```

`files::write(root, &rendered)` writes the set; `files::check` returns
one `Stale` per file that is missing or differs, which is what a
`gen --check` reports. Both take paths relative to the root and refuse
any that could leave it.

## Errors

Every registry error carries the file, line, column and a fix hint. A
`kind` error carries the line; `KindError::located(CONFIG)` turns it
into a registry error with the file name, so a forge crate prints one
error shape whatever went wrong.

## Forge-only extensions

A forge may add sections to its schema next to `kind::WORKFLOWS`, and
kinds and argument keys through `Extras`. Each is accepted only by that
forge. `kind::portable(&raw, &extras)` returns one `Finding` per
forge-only kind or key a row uses, so the forge crate can report which
rows would not survive a move to another forge. A row with no findings
renders on every forge.

## Starting a repository

`detect::detect` proposes rows from a repository's tracked files (a
`flake.nix` gives a `gate` row; a `nixpkgs-lock` input in `flake.lock`
gives `update-pins`), and `detect::seed_init` writes the first config
file from them, refusing to overwrite one that exists.

## Versioning

The same input and the same pipelith version give the same bytes. A
change to the bytes the YAML writer or the generated header emits is at
least a minor version, with a changelog entry naming it, since it
changes every consumer's generated files. Pin a version, and read the
changelog before moving it.
