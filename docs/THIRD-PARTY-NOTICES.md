# Third-party notices

`pipelith` ships **0 direct dependencies**, which pulls in 0 crates in
total. This file says what the crate links, why the list is empty, and
what licence the set carries.

## Why there are none

The library's runtime dependencies are the Rust standard library only,
and every dependency, dev-dependencies too, needs a row in `SPEC.md`
saying why (SPEC.md V6). A YAML writer, a table parser and a drift check
are small enough to own; a dependency here would be one more thing every
forge crate inherits.

## Not dependencies: the tools in the gate

These appear in the dev shell and the gate, and are **not** linked into
`pipelith`. A consumer building the crate never sees them. Neither is
`pipelith-dev`, the `publish = false` workspace member that renders this
table.

- [`hk`](https://github.com/jdx/hk): the gate runner.
- [`pkl`](https://github.com/apple/pkl): evaluates `hk.pkl`.
- [`pklith`](https://github.com/pr0d1r2/pklith): materializes the hk
  steps from `.pklith`.
- [`microlith`](https://github.com/pr0d1r2/microlith) (`mth`): owns the
  `SPEC.md` format and checks it.
- [`sherd`](https://github.com/pr0d1r2/sherd): checks the federated spec
  and holds the coverage floor.
- [`itok`](https://github.com/pr0d1r2/itok): token counting for the
  per-file ceilings.
- [`actionlint`](https://github.com/rhysd/actionlint) and
  [`zizmor`](https://github.com/zizmorcore/zizmor): lint the hand-written
  CI workflow.
